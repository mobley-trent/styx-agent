# Coding workflow

1. Understand the request and the repository's conventions before editing.
2. Locate the relevant code; prefer reading whole files over guessing.
3. Make the smallest change that satisfies the request.
4. Match the project's existing style, error handling, and test conventions.
5. Verify with the project's own commands (typecheck, lint, tests) and read
   the output rather than assuming the outcome.
6. Report what changed, what you verified, and what remains uncertain.
